01

系统总览

目标、边界、分层与运行时生命周期

Concept UrbanChain v3 是一个用 C++17 与 Qt 6 Widgets 实现的城市轨道交通线网桌面工具。输入是一张模拟城市地图（带权站点图 + 矢量背景），用户可以编辑站点、区间、线路和运营参数，查询任意时刻的出行路径，并把结果保存回文件。所有核心数据结构（除栈和队列外）均为自行实现。

1.1 v3 的边界

本版包含

地图/线路/线网模型、文件读写、图形编辑、时间相关导航、背景渲染、平滑线路、双语界面、撤销重做、单元测试与 UI 自动化测试。

本版不包含

自动规划（站权重、OD、R1–R6、模拟退火）、增量规划、真实地理数据、背景图形编辑器、可编辑精细轨迹点。

定位：v3 是“可运行、可编辑、可导航、可测试”的底座；v4 的自动规划只通过 Network 与 Router 的只读接口接入，不修改 v3 数据结构。

03

数据结构层

自写容器与算法：实现、复杂度、使用位置

课程约束要求除栈和队列外的基础数据结构自行实现。v3 的业务核心（core / io / nav / edit）不使用 std::vector、std::unordered_map、std::priority_queue 等容器，统一使用 src/ds。Qt 层允许使用 Qt 容器/控件用于界面。

3.1 DynamicArray<T>

项目实现
存储连续堆数组 T* data_，size_、capacity_
扩容空数组首次 8；之后容量 ×2，直到满足需求；元素移动构造
拷贝/移动深拷贝；移动接管指针并把源置空
常用操作push_back、pop_back、erase(index)、resize、reserve、at（越界抛出 std::out_of_range）
复杂度随机访问 O(1)；尾部插入均摊 O(1)；中间删除 O(n)；扩容 O(n)
约束元素需可默认构造（resize 使用 T()）

使用位置：站点表、边表、线路站点序列、区段运行时间、候选路径链、撤销栈、邻接表等。

3.2 HashMap<K,V,Hash>

项目实现
冲突处理链地址法：每个桶是 Node* 链表
哈希Fnv1aHash（字符串）、IntHash（64 位混合哈希）
扩容装载因子 > 0.75 时桶数 ×2，节点重新挂链
接口insert / set / find / contains / clear / forEach
复杂度平均 O(1)，最坏 O(n)（全部冲突）

使用位置：Map::stationIndex_（站点字符串 ID → 下标）、Network::transfers_（64 位换乘键 → 秒数）。

3.3 BinaryMinHeap

完全二叉树顺序存储在 DynamicArray<HeapItem> 中，HeapItem{double key; int value;}。比较规则：先比 key，key 相同比 value。Dijkstra 使用惰性删除：每次松弛都 push，弹出时若 key 大于当前 dist 则跳过。

复杂度：push/pop O(log n)，top O(1)。

3.4 UnionFind

并查集采用按秩合并 + 两遍路径压缩。find 先找到根，再把路径上所有节点直接挂到根；unite 按秩合并并维护连通分量计数。用于 Map::isConnected()。

复杂度：均摊 O(α(n))，α 为反阿克曼函数，实际近似常数。

3.5 Queue / Stack

队列用动态数组 + 头指针，出队只移动 head，超过 64 且超过总长一半时压缩；栈直接复用动态数组尾部。两者均为 O(1) 均摊。v3 生产路径主要用它们做课程结构演示，核心测试覆盖其行为。

3.6 QuickSort

实现对 DynamicArray 的原地排序：三数取中选枢轴，Hoare 式双指针分区，小区间（< 16）改用插入排序，递归较小区间、循环较大区间以控制栈深。平均 O(n log n)，最坏 O(n²)，原地 O(log n) 栈空间。

使用位置：Network::transferRecords() 按“站点 → 来源线路 → 目标线路”排序，保证保存出的 `.cuc3l` 中 TRANSFER 行顺序稳定。

4.2 Map：三种图表示同时维护

Map 是最核心的数据结构：它保存站点数组、站点 ID 哈希表、邻接表、边表、两个 n×n 矩阵（成本/长度），以及背景要素数组。

成员类型用途
stations_DynamicArray<Station>站点数组，下标即内部 Index
stationIndex_HashMap<string, Index>外部 ID → 内部下标
adjacency_DynamicArray<DynamicArray<AdjEdge>>邻接表，遍历与路径算法
edges_DynamicArray<EdgeRecord>边表，保存/统计；边 ID 即下标
matrixCost_扁平 DynamicArray<double>n×n 建设成本矩阵，O(1) 判边
matrixLength_扁平 DynamicArray<double>n×n 几何长度矩阵
background_DynamicArray<BackgroundFeature>背景矢量要素

为什么同时维护三种图表示

  • 邻接矩阵：hasEdge(u,v)、edgeCost、线路合法性校验需要 O(1) 判边；地图通常较稠密，n 不大。
  • 邻接表：遍历邻边、Dijkstra 只访问存在的边，避免扫描 n²。
  • 边表：保存文件、统计边数、删除边时重建；边 ID 与边表下标一致。

关键操作与复杂度

操作行为复杂度
addStation追加站点、更新哈希、扩容邻接表与两个矩阵O(n²)（矩阵复制）
addEdge写入边表、双向邻接表、矩阵；拒绝自环/重复/负成本O(1)
removeEdge从边表删除，重建邻接表与矩阵，更新边 IDO(n² + m)
setEdgeWeight同时更新边表、双向邻接项、矩阵O(deg(u)+deg(v))
isConnected并查集合并所有边O((n+m)·α(n))
findStation哈希查找平均 O(1)
一致性不变量：对每条边，边表记录、两个方向的邻接项、矩阵的对称两个格子必须同时存在且 cost/length 一致；边 ID 必须等于边表下标。removeEdge 通过整体重建保证这一点。

4.3 BackgroundFeature：背景矢量要素

enum class BackgroundKind {
    Region, Water, Park, Road, River, Coast, Boundary, Mountain
};

struct BackgroundFeature {
    std::string id;
    BackgroundKind kind = BackgroundKind::Boundary;
    bool closed = false;
    double width = 0.0;          // 线状要素的数据宽度
    DynamicArray<Vec2> points;   // 折线/多边形顶点
};
类型闭合宽度语义渲染
region是忽略城市地面浅色填充 + 细边
water是忽略湖泊/闭合水面填充
park是忽略绿地填充 + 描边
road否路面宽度（数据坐标）深色外框 + 浅色路面
river否河宽（数据坐标）河岸 + 水面
coast否海岸线宽度蓝色线
boundary可闭合忽略虚线行政边界
mountain否忽略棕灰虚线/等高线

背景只参与显示：不进入导航、长度、成本或图算法。渲染时按“地面 → 水体/公园 → 道路 → 河流 → 海岸 → 边界/山体”的图层顺序绘制；道路、河流、海岸会被裁剪到 region 多边形内。

4.4 Line 与 LineOps

线路是地图上的简单路径：不允许重复站点、相邻站点必须有地图边、至少 2 个站点。线路存储站点内部下标，保存时再映射回字符串 ID。

struct HeadwayPeriod { int startSec; int endSec; int headwaySec; };

struct LineOps {
    DynamicArray<double> segmentRunSec;  // 长度 = 站点数 - 1
    double dwellSec = 30.0;
    DynamicArray<HeadwayPeriod> headway; // 有序、不重叠
    int headwayAt(int timeSec) const;    // 无可用时段返回 0
};
校验项规则
站点数≥ 2（kMinStationsPerLine = 2）
站点下标必须在地图范围内
重复站点禁止（简单路径）
相邻边每一对相邻站点必须 map.hasEdge
区段运行时间数量 = 站点数 − 1，且非负
停站时间非负
发车间隔至少一段；start < end；interval > 0；有序不重叠

headwayAt 使用线性扫描，返回 timeSec ∈ [startSec, endSec) 的 interval；否则返回 0，表示该时刻不可乘车。

4.5 Network 与换乘表

Network = Map + DynamicArray<Line> + 换乘哈希表。线路没有单独的持久化 ID：线路序号就是它在数组中的下标，文件中的 LINE 顺序决定序号。

struct TransferRecord {
    Index station = kInvalidIndex;
    int fromLine = -1;
    int toLine = -1;
    double seconds = 0.0;
};

换乘键编码为 64 位：

key = (station << 42) | (fromLine << 21) | toLine

隐含限制：站点数、线路数均小于 2²¹。默认换乘时间 120 秒；transferTime 未命中时返回默认值。

removeLine(index) 会：删除线路 → 重排后续线路的 id → 读取全部换乘记录 → 清空换乘表 → 对每条记录，若 from/to 等于被删线路则丢弃，否则把大于 index 的线路号减 1 → 重新写入。

validate() 只校验每条线路，不强制地图连通；v3 编辑过程中允许孤立站点，导航对不可达返回“无路径”。

4.6 Catmull-Rom 样条

线路显示使用向心 Catmull-Rom（alpha = 0.5），曲线精确经过所有站点。实现位于 src/core/spline.cpp，仅用于渲染与命中检测，不参与长度、时间或规划。

输入关键点 P0..Pn
1. 首尾各加一个反射虚拟点
2. 用相邻点距离的 alpha 次幂构造节点向量 t
3. 对每个真实段 [P1,P2]，在 t 上采样 S 个参数
4. 用 de Casteljau 式线性插值求点
5. 拼接输出；线渲染每段 S = 24

复杂度：O(n·S)，S 固定；对线路长度 P 的线段，渲染点是 O(P)。

5.3 线路文件语法

CUC3L 1
LINE <颜色> <名称...>
STOPS <站点ID...>
RUN <区段运行秒数...>
DWELL <停站秒数>
HEADWAY <开始秒> <结束秒> <发车间隔秒>
...
TRANSFER <站点ID> <来源线路序号> <目标线路序号> <秒数>
...
END
  • 线路序号 = LINE 出现顺序，从 0 开始；TRANSFER 使用这个序号。
  • STOPS 顺序即行驶顺序；相邻站点必须在地图中有边，且不允许重复。
  • RUN 数量必须等于站点数 − 1；DWELL 是中间站停站时间。
  • HEADWAY 可重复；区间为 [start, end)，必须有序、不重叠，至少一段。
  • TRANSFER 是有向记录；同一换乘站每条线路分别记录到其他线路的时间。
  • 线路颜色支持 0xRRGGBB 或十进制；保存输出大写十六进制。

5.4 读取流程

  1. 按 UTF-8 读取，首行去 BOM，行尾去 CR；跳过空行和 # 注释。
  2. 读取版本头，只接受 1/2/3；根据版本决定是否解析 BG 和 width。
  3. 地图先解析到临时 Map；站点 ID 重复、边引用未知站点、BG 数量不匹配都会带行号报错。
  4. 线路先解析到临时 DynamicArray<Line> 与临时换乘记录；构建临时 Network，复制地图，加入线路和换乘，调用 validate()。
  5. 全部成功后才替换当前文档；Editor::load 会清空撤销/重做并重置 dirty。

5.5 保存流程

  1. Editor::save 先调用 network_.validate()，线路非法则拒绝保存。
  2. 根据扩展名选择版本：.cuc3m2 → v2，.cuc3m3 → v3；旧 .cuc3m 拒绝写出。
  3. v2 若存在任何 width > 0 的背景要素，直接拒绝并提示改用 v3。
  4. 浮点统一 17 位有效数字；站点/边按内部数组顺序写出；换乘记录排序后写出。
  5. 文件打开失败/写入失败返回错误字符串，由 UI 弹出“保存失败”。
已知格式限制：名称取整行剩余内容，不支持换行/转义；背景 ID 与站点 ID 都是不含空格的 token；线路序号隐式依赖 LINE 顺序；v2 无宽度字段；旧程序不能读取新文件。

编辑控制器

与界面无关的文档层：事务、撤销、索引重映射

Editor 是 UI 与核心模型之间的唯一文档入口。它拥有一个 Network、两个 DynamicArray<Network>（撤销/重做）和一个 dirty_ 标志。Qt 层不直接修改 Network。

6.1 API 分组

分组方法说明
文档newDocument / load / save / validate / isDirty新建清空历史；加载/保存事务化
站点nextStationId / addStation / moveStation / renameStation / removeStation删除会重建索引映射
区间addEdge / removeEdge / setEdgeWeight默认成本/长度 = 欧氏距离
线路addLine / removeLine / appendStop / removeLastStop / setLineStations / replaceLineappend 默认 120 秒区段；addLine 默认 30 秒停站、300 秒间隔
换乘setTransferTime / setTransferTimes批量版本只产生一次撤销快照
历史canUndo / canRedo / undo / redo整网快照

6.2 撤销 / 重做模型

修改前：
  pushUndo(): undo_.push_back(network_); redo_.clear();
  若修改失败：rollbackUndo(): undo_.pop_back();
  成功：dirty_ = true;

撤销：
  redo_.push_back(std::move(network_));
  network_ = std::move(undo_.back());
  undo_.pop_back(); dirty_ = true;

重做：
  undo_.push_back(std::move(network_));
  network_ = std::move(redo_.back());
  redo_.pop_back(); dirty_ = true;
为什么用整网快照：v3 地图规模小，快照实现简单、绝对可靠；代价是每次编辑 O(V+E+L) 内存。若后续追求大图性能，可换成命令模式或差量快照。

6.3 删除站点的索引重映射

删除站点不是简单 erase：站点下标会整体左移，所有线路站点、区间端点、换乘键都要同步。算法：

  1. 检查该站点是否被任何线路使用；若使用则拒绝，提示先从线路移除。
  2. 建立 oldIndex → newIndex 映射，被删站点为 kInvalidIndex。
  3. 新建 Map：按旧顺序加入除被删站点外的所有站点；加入不涉及被删站点的边，端点用映射转换。
  4. 复制全部背景要素（这一步最初遗漏，后补上）。
  5. 新建 Network，按旧线路顺序复制线路，站点序列用映射转换；运营参数原样保留。
  6. 复制换乘记录：跳过涉及被删站点的记录，其余站点键用映射转换；线路号不变。
  7. 对临时线网调用 validate()，通过后压入撤销栈并替换当前网络。

复杂度 O(V + E + L·S + T)，其中 S 为单线站数，T 为换乘记录数。

6.4 保存前校验

Editor::save 先调用 network_.validate()，检查每条线路：站点数、下标、重复站、相邻边、区段运行时间数量/符号、停站时间、发车间隔。校验失败时不会写文件，UI 显示具体错误。

6.5 事务化编辑模式

所有修改方法遵循同一模式：

bool Editor::op(...) {
    if (!前置检查) return false;
    pushUndo();
    if (!底层操作) { rollbackUndo(); return false; }
    dirty_ = true;
    return true;
}

因此失败操作不会留下“半个修改”，也不会污染撤销栈。

07

时间相关导航

状态图、等待模型、Dijkstra、路径重建与 FIFO 限制

7.1 为什么不能只在站点图上跑 Dijkstra

换乘代价取决于“从哪条线来、换到哪条线”；同一站点在不同线路上是不同状态。若只存站点距离，无法区分“在 Red 上到达 Central”和“在 Blue 上到达 Central”。因此状态定义为：

state = (station, currentLine)
stateId = station * lineCount + lineIndex
起点对每条经过起点的线路，计算初始等待并进入状态
乘车沿线路前/后移动：停站时间 + 区段运行时间
换乘同站换到另一条线：走行时间 + 目标线等待
终点在所有线路的终点状态中取最小到达时间

7.2 时间模型

事件代价说明
初始等待headwayAt(departSec) / 2乘客到达站台时刻的期望等待
乘车dwellSec + segmentRunSec[i]停站 + 区段运行；起点段也加一次停站
换乘transferWalk + headwayAt(floor(arrival+walk)) / 2先走到站台，再按到达站台时刻查目标线间隔
到达状态时间不再加终点停站

所有时间以秒为单位存为 double，内部保留秒级精度；界面显示时四舍五入到分钟。

7.3 Dijkstra 伪代码

findRoute(network, origin, destination, departTime):
  dist[state] = INF, prev[state] = -1
  heap = empty
  for each line L serving origin:
      h = L.headwayAt(floor(departTime))
      if h > 0:
          relax(origin, L, departTime + h/2, from = -1)

  while heap not empty:
      (t, state) = heap.pop()
      if t > dist[state] + EPS: continue
      (s, l) = decode(state)
      pos = index of s in line l
      if pos+1 exists:
          relax(next, l, t + dwell + run[pos], state)
      if pos-1 exists:
          relax(prevStop, l, t + dwell + run[pos-1], state)
      for each other line L2 at s:
          walk = transferTime(s, l, L2)
          h = L2.headwayAt(floor(t + walk))
          if h > 0:
              relax(s, L2, t + walk + h/2, state)

  best = min over lines of dist[(destination, line)]
  reconstruct via prev[] and group consecutive same-line states into legs

复杂度：状态数 O(n·L)，每个状态松弛 O(L) 条换乘边，使用二叉堆，时间约 O(nL·(L + log(nL)))，空间 O(nL)。v3 地图规模小，完全可接受。

7.4 示例时间线

示例线网：Red（WEST → CENTRAL → EAST → NE，间隔 300 秒，停站 30 秒，区段 120 秒），Blue（NORTH → CENTRAL → SOUTH → SE，间隔 420 秒），CENTRAL 双向换乘走行 90 秒。查询 WEST → SE，08:00 出发：

步骤计算时刻
初始等待 Red300 / 208:02:30 上车
WEST → CENTRAL30 停站 + 120 运行08:05:00 到达
CENTRAL 换乘90 走行 + Blue 420/208:10:00 上 Blue
CENTRAL → SOUTH30 + 12008:12:30
SOUTH → SE30 + 12008:15:00 到达

结果：1 次换乘，两段行程；界面按分钟显示为 08:03–08:05 与 08:10–08:15。

7.5 路径重建

prev[state] 保存前驱状态；从最优终点状态回溯到起点，得到状态链；再把连续同一线路的状态合并为 JourneyLeg。换乘次数 = 行程段数 − 1。

7.6 FIFO 限制（答辩重点）

Dijkstra 的正确性依赖 FIFO：晚到达站台不应导致更早出发/到达。v3 的等待函数是 w(t) = H(t)/2，在分时段间隔的边界，H(t) 可能突然变小，导致 t + w(t) 非单调，于是“首次弹出即最优”的假设可能失效。

v3 的实际处理：演示数据使用单一发车间隔，FIFO 成立；代码按 Dijkstra 实现。分时段边界、非 FIFO 的处理（限制参数域、允许自愿等待、标签修正/时间离散）明确留给 v4 实验决定。文档和答辩中应主动说明这一边界，而不是声称任意参数下都严格最优。

7.7 其他边界

  • 起点 = 终点：直接返回 found、到达时间 = 出发时间、0 段。
  • 没有线路 / 起点不在任何线路 / 起点时刻不在运营窗口：返回未找到。
  • 换乘时目标线路在该时刻无班次：该换乘边不生成。
  • 并列最短路径：当前实现按状态编号扫描取第一个最小值，没有做“时间相同取换乘更少”的字典序。
  • 线路双向行驶：乘车边同时向前和向后松弛。

渲染与交互

8.1 坐标系

数据坐标 y 轴向上，Qt 场景坐标 y 轴向下。所有地图坐标在进入渲染前转换为 (x, -y)；新增站点、拖动站点在提交给 Editor 前再转回 (x, -y)。站点图元使用 ItemIgnoresTransformations，大小固定为屏幕像素；线路/背景宽度使用场景数据单位，随缩放变化。

8.2 背景渲染流水线

1region浅色地面填充 + 细描边
2park / water绿地/水面填充 + 描边
3road外框宽 width+max(0.012, 0.18w)，路面宽 0.72w

8.3 线路平滑与命中检测

  • 每条线路把站点场景坐标送入 catmullRomSpline(points, 24, 0.5)，再拼成 QPainterPath。
  • 选中线路用更宽的半透明光晕 + 6.5px 线；普通线路 5px；均为 cosmetic 笔画。
  • 绘制预览（Draw Line）把鼠标位置作为额外关键点加入样条，形成实时曲线。
  • lineAt(scenePos, threshold) 遍历采样点折线，用点到线段距离判断；阈值是“12 屏幕像素 / 当前缩放”，因此不同缩放下手感一致。
  • 地图区间（灰色基础设施线）仍是直线，使用 10 像素阈值做删除命中。

8.5 视图操作

  • 滚轮缩放，锚点在鼠标下；总缩放限制在 0.001–1000。
  • 中键拖动平移，通过滚动条位置实现；光标切换为 ClosedHand。

  • 刷新时重建站点图元；选中站点/线路按索引恢复；场景包围盒由站点 + 背景要素共同决定。

8.6 StationItem

站点图元是 14×14 像素椭圆，ItemIgnoresTransformations 使其不随缩放变大；子项 QGraphicsSimpleTextItem 显示站名（9pt），并设置 tooltip。选中时填充变为琥珀色、描边加粗。图元只负责显示，不处理拖动；拖动由 MapView 统一命中。

12.2 算法深度

  • 时间相关最短路：状态图 + 期望等待 + 换乘 + 路径重建，不是简单最短路。
  • 事务式编辑与撤销：每次修改先快照，失败回滚；删除站点做全局索引重映射。
  • Catmull-Rom：可视化平滑，且命中检测按采样曲线做几何距离。
  • 格式版本化：v1/v2/v3 兼容读取，扩展名决定保存版本，v2 拒绝宽度丢失。
  • UI 与业务分离：Editor 可被 Web 前端复用；v4 规划模块只读接入。

12.3 讲解建议

  1. 先展示“地图 → 编辑 → 导航 → 保存”完整链路，证明软件可运行。
  2. 再讲三层结构：UI / Editor / Network，强调为什么编辑逻辑不放在 Qt 里。
  3. 重点讲状态图导航和撤销/重映射，这两处最能体现数据结构与算法能力。
  4. 最后讲文件版本、双语、测试与已知限制，主动说明 FIFO 等边界。

14

答辩问答速查

按“结论 → 原因 → 代码落点”组织

为什么导航要建 (站点, 线路) 状态图，而不是直接在站点图上跑 Dijkstra？
换乘代价依赖“从哪条线来、换到哪条线”，同一站点在不同线路上是不同状态。状态图把线路身份编码进节点，换乘边只在同站不同线之间生成。实现：Router::findRoute，状态编号 station*lineCount+lineIndex。
等待时间为什么是发车间隔的一半？
采用静态期望等待模型：乘客随机到达站台，若发车间隔为 H，平均等待 H/2。起始等待用出发时刻的 H；换乘等待用“到达站台时刻”的 H，而不是统一用出发时刻。代码中每次换乘先 floor(t + walk) 查 headwayAt。
什么是 FIFO 问题？你的实现严格正确吗？
Dijkstra 要求“晚到达不会更早出发”。v3 的等待是 H(t)/2，分时段间隔在边界可能突然变小，使 t+H(t)/2 非单调。演示数据是单一间隔，FIFO 成立；代码按时间相关 Dijkstra 实现。分时段边界的情形明确留给 v4 实验处理，没有声称任意参数下都严格最优。
为什么线路必须是简单路径、不允许环线？
v3 基础约束：线路内部不重复站点，避免线路内部绕圈导致状态图/行程重建歧义；线路首尾不闭合，避免绕行度与终点定义复杂化。不同线路可以共享站点和区间。约束在 Line::validate 与 Editor::appendStop 中检查。
为什么同时维护邻接矩阵、邻接表和边表？
矩阵用于 O(1) 判边和线路合法性检查；邻接表用于遍历/Dijkstra；边表用于保存、统计和删除边时重建。三者由 Map 的增删改操作同步维护，removeEdge 通过整体重建保证边 ID 与矩阵/邻接一致。
撤销/重做怎么实现？为什么不用命令模式？
每次修改前把整个 Network 拷入 undo_ 栈并清空 redo；撤销/重做在栈之间移动快照；失败操作 rollback 弹出快照。v3 图规模小，快照简单可靠、天然支持所有操作。代价是内存 O(编辑次数×图规模)，后续可替换为命令模式。
删除站点时索引怎么处理？
删除会改变所有后续站点下标。算法先检查站点未被线路使用，再建立 old→new 映射，重建 Map（站点、边、背景），重建线路站点序列，重映射换乘站点键，最后 validate 后提交。见 Editor::removeStation。
换乘键怎么存？有什么限制？
64 位编码 (station<<42)|(fromLine<<21)|toLine，哈希表存秒数；默认 120 秒。隐含限制是站点/线路数都小于 2²¹，课程地图远小于此。保存时 transferRecords() 排序，输出确定。
为什么地图文件改成 .cuc3m2/.cuc3m3？怎么兼容？
背景要素和线宽需要格式扩展。扩展名与版本绑定：v3 带宽度，v2 无宽度，旧 .cuc3m 只读。读取由文件头版本决定，三种都能读；保存默认 v3，v2 仅在没有宽度时允许；旧路径保存会转“另存为”。
Catmull-Rom 平滑会影响导航/成本/规划吗？
不会。样条只在 MapScene 渲染与命中检测中使用；线路长度仍按地图边长度累计，导航按区段运行时间，成本按地图边权。平滑曲线可能轻微偏离直线区间，这是纯视觉效果。
背景是怎么画出“地图感”的？
按图层：region 地面 → water/park 面 → road（外框+路面）→ river（河岸+水面）→ coast → boundary/mountain 虚线 → 地铁区间/线路 → 站点。道路/河流宽度用数据坐标，随缩放变化；所有线状要素裁剪到 region 多边形内。
双语怎么做到即时切换？
英文原文作键的静态词典 + QSettings 持久化；切换后 retranslateUi() 统一刷新动作、菜单、停靠栏、按钮、标签；中文时安装 qtbase_zh_CN.qm，标准对话框按钮也中文。核心错误由 localizeMessage 做精确/前缀翻译。
保存失败会不会损坏原文件？
不会。打开是事务式：先解析到临时 Map/Network，校验通过才替换内存文档；保存前先 validate，扩展名/宽度不合法会在打开文件流之前返回错误。写文件失败会报错，但不会把半个模型写进去。
你的数据结构复杂度怎么样？
站点 ID 查找平均 O(1)；Dijkstra O(nL·(L+log(nL)))；撤销快照 O(图规模)；删除边 O(n²+m)；删除站点 O(V+E+L·S+T)；样条 O(线路站数×采样数)。课程规模下均可接受，瓶颈主要在撤销快照和全源/多OD 评价（后者属于 v4）。
为什么没有用最小生成树？
课程设计早期曾考虑 MST，但 v3 的线网规划目标是覆盖/成本/时间/换乘/绕行/短线路惩罚的多目标组合，MST 只能给出最小连通骨架，无法表达线路集合与换乘结构；当前 v3 本身就是手动编辑 + 导航，MST 不是合适的主算法。后续 v4 的规划算法会按规格另做设计。
如果地图很大，哪里最先成为瓶颈？
撤销快照的整网拷贝、Map::addStation 的 O(n²) 矩阵扩容、removeEdge 的 O(n²) 重建，以及未来 v4 的全 OD 路径评价。v3 面向课程规模（几十到几百站）；大图需要稀疏矩阵/差量撤销/增量评价。
