## 1. 项目背景

**原始项目。** Concept UrbanChain（概念都市链）是一个概念性的城市轨道交通系统沙盒，最初以 Python + pygfx 实现原型，已具备站点/线路数据模型、GPU 渲染、地图切换、编辑、导入导出、中英双语等能力。原项目定位为"把各种算法塞进去验证数学是否成立"的个人实验。

**课程背景。** 本项目同时作为《数据结构课程设计》的**自拟课题**。指导书中的 19 个题目均为"示例"，鼓励扩展与创新；课程硬约束为：

- 使用 C / C++；
- 除栈与队列外，数据结构需自行实现；
- 3 人小组（难度大时可 4 人），需答辩与撰写报告；
- 发现抄袭直接不及格。

**项目定位。** 在原型基础上迁移并扩展为一个完整的"地图 → 线路 → 导航 → 规划"系统，既作为可运行软件，也作为数据结构与算法设计能力的展示载体。

### 2.1 功能目标

1. 导入/导出包含背景矢量图层与带权站网的地图文件；

- 通过"手动规划 vs 自动规划""不同算法/参数对比"体现设计深度。

### 2.3 v1 非目标

## 4. 数据设计（v1 已确定部分）

### 4.1 地图文件 `.cuc3m3` / `.cuc3m2`（兼容旧 `.cuc3m`）

包含三部分，共用同一坐标系：

1. **背景矢量图层**：行政区边线、山脉、河流等，与算法无关；
2. **地铁信息图层**：
   - 站点：唯一 ID、名称、坐标；
   - 连接关系：**无向带权图**，本质只有"节点 + 权值"；
   - 概念上任意两节点之间存在边，但为避免数据膨胀，只存储有意义的连接，未存储的连接权值视为 **INF**；
   - 存储的边整体连通，任意两站可沿路径到达。
3. **坐标系**：全局唯一，背景层与信息层共享。

规则：

- 站点唯一归属于地图，线路通过 ID 引用站点；
- 线路必须沿地图中的边行驶，线路是图上的路径。

### 4.2 线路文件 `.cuc3l`

每条线路包含：

- 线路 ID、名称、颜色；
- 有序站点序列（沿地图边）；
- **站间散点序列**（`fine_trajectory` 思路）：纯视觉效果，使线路不是折线多边形，不参与算法；
- 运营参数：
  - 区段运行时间；
  - 停站时间；
  - **分时段发车间隔**（用于计算等待期望）；
  - **换乘走行时间**：按线路保存，有向记录。例如 4 线换乘站，每条线路分别记录到另外 3 条线路的换乘时间；
- 预留 **已建成 / 规划中** 状态，为后续增量规划留出接口。

### 4.3 站点权重模型

**目的。** 在缺少真实客流数据的条件下，用空间几何近似站点的重要度（客流代理）。

**生成步骤。**

1. 对所有站点做 **K-means 聚类**，簇数 `K` 为输入参数；
2. 计算每个簇的中心；
3. 计算两类近心距离：
   - `d1_i`：站点 `i` 到**所属簇中心**的距离（局部近心）；
   - `d2_i`：所属簇中心到**全局中心**的距离（区域近心）；
4. 距离按地图尺度 `R` 归一化；
5. 计算权重：

```
w_i = (d1_i + ε)^(-1) · (d2_i + ε)^(-k)        (k ≥ 0, ε > 0)
w_i ← w_i / mean(w)                             (或 / sum(w))
```

6. 归一化方式由参数 `weight_norm` 决定。

**说明。**

- 局部维度指数固定为 1，区域维度指数为 `k`；`k = 0` 表示只看局部，`k` 越大区域中心性影响越强；
- `ε` 用于避免距离为 0 时除零；K = 1 时自动退化为"到全局中心的单中心权重模型"。

**全局中心模式**（参数 `global_center_mode`）：

| 模式 | 定义 | 说明 |
|---|---|---|
| `station_mean` | 所有站点坐标均值 | 与 K-means 目标一致；密集区影响较大 |
| `cluster_mean` | 所有簇中心坐标均值 | 每簇等权；结果依赖 K 与簇大小分布 |
| `custom` | 用户给定坐标 `(center_x, center_y)` | 人工指定真实主中心 |

**默认规则（v1）：**

- 单中心 / 简单地图 → `station_mean`；
- **多中心城市 → `custom`**，由用户指定主中心，**不默认使用 `cluster_mean`**（单点均值可能落在非城区，制造"假中心"并系统性压低真实中心）；
- `cluster_mean` 仅在各簇地位大致对等、且明确需要等权时手动选用；
- 增加合理性告警：若全局中心距最近簇中心过远、或簇中心呈明显多峰，提示改用 `custom`。

**多中心的结构性限制。** 单全局中心本质上假设城市只有一个中心。对天津（主城 + 滨海新区）这类多中心城市，"到单一中心的距离"会带来系统性偏差。v1 通过 `custom` 规避；真正的解法是 **`multi_center` 模式**（维护中心集合，区域近心度取到最近中心的距离），计划放入 v2。

**距离度量。** v1 固定为**欧氏距离**，`distance_metric` 字段保留以便后续扩展。

**归一化尺度 `R`。**

```
R = 所有站点到全局中心距离的均值（为 0 时取 1）
```

计算顺序固定为：**K-means → 簇中心 → 全局中心 → R → d1/d2 → 权重 → 归一化**。

**本模块输入参数：** `K`、区域指数 `k`、稳定项 `ε`、`global_center_mode`、`center_x/y`（仅 `custom`）、`weight_norm`。

### 4.4 坐标与距离

- 地图使用统一坐标系，背景层与信息层共享；
- 所有距离在参与权重计算前按 `R` 归一化，使参数在不同地图间可比；
- K-means 聚类使用欧氏距离（v1）。

### 4.5 OD 需求模型

站权重 `w_i` 同时作为出行发生/吸引强度。任意两站之间的需求采用**重力模型**：

```
OD_ij ∝ w_i · w_j / d_ij^β
```

- `β` 为输入参数（距离衰减指数）；
- **当 K > 1 时强制 β = 1**（用户约定）；
- `d_ij` 为两站之间的直线距离（v1 欧氏距离，精确轨迹不参与）；
- 按无序站对计算，往返视为对称；
- 需求只用于评价（需求加权指标）与规划中的需求累加，不改变地图数据本身。

## 5. 功能模块

### 5.1 地图模块

- 导入 `.cuc3m3` / `.cuc3m2` / 旧 `.cuc3m`：解析背景矢量图层与带权站网；
- 导出 `.cuc3m3` 或 `.cuc3m2`（按扩展名选择版本）；
- 地图切换（沿用原型的多地图注册表思路，可运行时增删）。

### 5.2 地铁模块

- 线路管理：创建、编辑、删除线路；
- 手动规划：用户绘制/调整线路；
- 自动规划：基于参数生成线路（见第 6 节）；
- 导入/导出 `.cuc3l`。

### 5.3 导航模块

**模型。** 时间相关最短路：

- 搜索状态为 `(站点, 当前所在线路)`，因为换乘代价取决于来源线路与目标线路；
- 起始等待：目标线路在出发时刻所属时段的发车间隔 / 2；
- 每段乘车：区段运行时间 + 中间各站停站时间；
- 每次换乘：换乘走行时间（线路数据） + 目标线路在到达时刻所属时段的发车间隔 / 2；
- 每段等待均按"到达时刻"查询对应时段频率，携带前序行程的时间偏移，不统一按出发时刻计算；
- 满足 FIFO 性质（晚到不会更早到达），可用 Dijkstra 正确求解；
- 内部计算精确到 1 秒，界面展示精确到 1 分钟。

**输入/输出。**

- 输入：出发站、终点站、出发时刻；
- 输出：推荐路径、预计到达时刻、总耗时、换乘次数、各段乘坐线路与时间。

### 5.4 UI

- v1 优先保证功能完整；
- 后续再做现代感视觉与交互优化；
- 规划参数通过对话框手动输入。

## 6. 规划子系统

### 6.1 输入参数（手动输入，v1）

| 参数 | 类型 / 默认 | 含义 |
|---|---|---|
| `cover_all` | bool / true | 是否要求覆盖全部站点 |
| `w_cost` / `w_time` / `w_transfer` / `w_coverage` | float / 0.4/0.3/0.2/0.1 | 目标权重（和为 1） |
| `beta` | float / 1.0 | 重力模型距离衰减指数；**K > 1 时强制为 1** |
| `k_station` | float / 待定 | 站台成本系数，与地图无关；线成本直接使用地图带权图的边权（成本公式见 6.2） |
| `max_lines` | int / 8 | 最大线路数（0 = 不限） |
| `max_line_len` | float / 自动 | 单线最大长度 |
| `min_line_len` | float / 0 | 最短线路，防止碎线 |
| `max_detour` | float / 1.5 | 绕行比上限（路径长 / 端点直线距离） |
| `candidate_k` | int / 20 | 每轮评估的候选线路数 |
| `local_search_iters` | int / 0 | 局部搜索迭代次数（0 = 关闭） |
| `seed` | int / 0 | 随机种子（保证可复现） |

站点权重参数（`K`、`k`、`ε`、`global_center_mode`、`center_x/y`、`weight_norm`）见 4.3。

### 6.2 评价指标（外部裁判）

| 指标 | 定义 | 方向 |
|---|---|---|
| 加权覆盖率 | `Σ_{被任一线路覆盖的站} w_i / Σ_i w_i` | 越高越好 |
| 总建设成本 | `Σ_{线路使用边的并集} w_e + k_station × Σ_i (平台数_i × w_i)` | 越低越好 |
| 需求加权平均出行时间 | `Σ(OD_ij × t_ij) / Σ OD_ij`；`t_ij` 的计算口径待定 | 越低越好 |
| 需求加权平均换乘次数 | `Σ(OD_ij × 换乘数_ij) / Σ OD_ij` | 越低越好 |
| 绕行度 | 每条线：按相邻站直线距离累计的线路长度 / 端点直线距离；取各线均值；精确轨迹不参与 | 越低越好 |
| 线路数 / 规划耗时 | 运营复杂度与效率 | 越低越好 |

**说明：**

- **平台数** = 经过该站的线路数（换乘站按线路数计）；
- **线成本直接使用地图带权图的边权 `w_e`**，不是输入参数；`k_station` 是唯一的成本输入参数；
- 覆盖率按站权重加权，不按站点数量；
- **不使用冗余度与线路均衡度**；
- 评价指标中保留内层没有直接优化的量（绕行度等），避免自己给自己打分。

### 6.3 内层规划算法（初选，待验证）

**候选方案：走廊识别 + 贪心线路生成。**

```
输入：带权图 G、参数
1. 选候选端点：度 = 1 的站 + 高权重站 + 空间极值点，取前 candidate_k 对
2. 候选线路：对每对端点求最短路（Dijkstra），按 max_detour 过滤
3. 打分：score = w_coverage·新增覆盖 − w_cost·成本 − w_time·时间 − w_transfer·换乘
4. 贪心选线：选 score 最高的一条，更新已覆盖站/需求，重复直到满足覆盖或达到 max_lines
5. 补全：对仍未覆盖的站，延长最近线路端点或新建短线
6. 局部搜索（可选）：延长/截短/交换端点，按评价指标改进
7. 输出 DesignResult（线路、边集、指标、告警）
```

**备选方案：** 线路生长法（从种子路径向两端逐步吸收未覆盖站），结果更自然，但参数与流程稍复杂，可作为第二种规划模式对比。

> 说明：v1 **不再使用最小生成树**。规划目标与算法以本节的参数与评价体系为准。

### 6.4 外层参数选择（后续版本）

- 输入：地图（带权图）；
- 输出：一组规划参数（字典）；
- 方法：**contextual bandit / 学习式选择器**（一次性决策，不是严格意义的强化学习）；
- reward：评价指标的组合（多指标归一化后合成）；
- 训练：在随机生成的地图上训练，留出测试集；
- 状态表示：先用固定长度地图统计特征（站数、边密度、度分布、空间范围、权重分布、连通性、直径等）；
- 状态：v1 不实现。

### 6.5 增量规划（后续版本，RL 适用）

场景：地图新增站点后需要补充规划，且**已建成线路不可拆除**，构成顺序决策问题。

MDP 草案：

| 要素 | 定义 |
|---|---|
| 状态 | 当前已建线网 + 新增站点 + 带权图 + 预算/约束 |
| 动作 | 将新站合法接入网络的增量操作（连边 / 延长线路端点 / 新建线路 / 建换乘），受动作掩码约束 |
| 转移 | 应用动作，确定性 |
| 奖励 | 评价指标的边际变化 − 违约惩罚 |
| 回合 | 从初始线网开始，按顺序加入一批新站，直到预算耗尽或站加完 |

约束讨论：**"不能拆老线路"是否允许插入/改道**尚未决定；倾向"只增不改"。v1 不实现。
