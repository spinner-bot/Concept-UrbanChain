# Concept UrbanChain v3 / v4 开发计划

> 版本：0.1（草案）
> 日期：2026-11-24
> 依据：`docs/项目计划书.md`、`docs/城市轨道交通线网规划模型与算法设计规格说明v2.0.md`

---

## 1. 目标与拆分理由

先做 **v3：不含自动规划的可运行软件**，测试通过后，再把 **自动规划** 作为独立模块加入形成 v4。

拆分理由：

- 自动规划依赖地图模型、线路模型、评价器、导航器，没有这些基础设施无法运行实验；
- 自动规划与核心软件耦合度低，适合作为独立模块接入；
- v3 先保证数据模型、文件、导航、测试正确，v4 只替换/新增规划层，降低联调风险。

## 2. v3 范围

### 2.1 包含

1. **自写数据结构**：动态数组、哈希表、二叉堆、并查集、栈、队列、常用排序；
2. **地图模型**：站点、无向带权图（邻接矩阵 + 邻接表 + 边表）、背景矢量要素（行政区/河流/海岸/山脉/区域填充）、连通性检查；
3. **线路模型**：站点序列、颜色、区段运行时间、停站时间、分时段发车间隔、按线路保存的换乘走行时间；
4. **线网模型**：地图 + 线路集合 + 校验；
5. **文件读写**：`.cuc3m` / `.cuc3l` 的 v1 文本格式（版本化，可扩展）；
6. **导航**：`(站点, 线路)` 状态图上的时间相关最短路，输出行程段与换乘次数；
7. **应用外壳**：Qt 6 Widgets 图形界面，编辑操作全部由鼠标与菜单触发；中英文双语，可在设置中即时切换；
8. **编辑控制器**：与界面无关的文档编辑、校验与撤销/重做，供当前界面和后续 Web 前端复用；
8. **测试**：数据结构、地图、线路、文件往返、导航用例。

### 2.2 不包含（留到 v4 或后续）

- 站权重、OD 需求、六项评价指标；
- 自动规划、候选生成、模拟退火、实验框架；
- 真实地理数据导入。项目采用**模拟城市**，背景使用自行设计的矢量要素，不需要栅格瓦片或在线地图；
- 图形界面视觉设计；
- 外层参数选择器、增量规划。

## 3. 模块与目录

```
src/
  ds/          自写数据结构（header-only 模板为主）
  core/        站点、地图、线路、线网
  nav/         时刻表、导航器
  io/          .cuc3m / .cuc3l 读写
  edit/        与界面无关的编辑控制器（撤销/重做、校验）
  ui/          Qt 6 Widgets 图形界面
    main_window  菜单、文件操作、窗口
    map_view     鼠标交互、缩放平移
    map_scene    场景渲染
    station_item 站点图元
tests/         自写测试框架 + 各模块测试
data/          示例地图与线路
docs/          设计与计划文档
```

## 4. 关键接口边界

- `Map`：只负责站点与带权图，不依赖线路与规划；
- `Line`：只描述线路自身与运营参数，通过 `Map` 校验合法性；
- `Network`：组合地图与线路，提供只读访问；
- `Router`：只读 `Network`，可被 v4 的评价器复用；
- `planner/`（v4）：只通过 `Network` 的只读接口与 `Router` 获取信息，不修改其内部状态。

v3 的 `Network` 与 `Router` 接口应保持稳定，v4 不修改 v3 数据结构即可接入规划模块。

## 5. v4：自动规划模块

- **输入构造**：站权重、OD 需求、规划参数、评价参数；
- **评价器**：R1~R6 完整评价，复用 `Router` 计算 R3/R4；
- **搜索器**：候选生成 + 动态修改算子 + 模拟退火/大邻域搜索；
- **实验框架**：配置、随机种子、结果日志、消融与敏感性分析；
- **输出**：线网结构 + 六维指标 + 搜索过程记录。

实验代码与生产代码分区存放，实验分支命名 `exp/<主题>`。

## 7. 版本管理

按 `specs/项目规范/版本管理规范.md` 执行：

- 按文件/模块小步提交，不积压；
- 实验在 `exp/*` 分支进行，合并必须 `--no-ff`；
- 不使用 squash、rebase 或强推；
- 阶段性完成后推送，推送前检查远端分歧；
- 运行中的实验日志只在检查点保留已核验内容，不把未完成输出标为最终结果。

## 8. 构建与测试

- 语言：C++17；
- 构建：CMake + Ninja；
- 测试：自写轻量测试框架，`ctest` 驱动。

**工具链（2026-11-24 确认）**：Visual Studio Community 2022
（`D:\VisualStudio\Packages`），自带 MSVC 14.44 与 CMake 3.31。仓库提供
`tools/build.bat`，自动定位 VS、初始化 MSVC 环境并构建；可用环境变量
`UC_VSPATH` 覆盖 VS 安装路径。MSVC 编译选项包含 `/utf-8`，避免中文注释在
GBK 代码页下被误解析。

**图形库（2026-11-24 安装）**：Qt 6.8.3 MSVC 2022 64 位，安装于
`F:\dev-tools\6.8.3\msvc2022_64`（采用 LGPLv3 动态链接）。`tools/build.bat`
会自动查找该路径并传给 CMake；也可用环境变量 `UC_QT_PATH` 覆盖。构建后由
`windeployqt` 自动把 Qt 运行库部署到 `build/`。

构建与测试入口：

```
tools\build.bat
build\uc_tests.exe
build\uc_ui_tests.exe
ctest --test-dir build --output-on-failure
build\urbanchain.exe
```

控制台编辑入口已移除，图形界面是唯一的编辑方式。编辑逻辑位于
`src/edit/`，Qt 层只负责事件翻译与渲染，后续可替换为 Web 前端。

开发自检入口（仅用于截图验证）：

```
urbanchain.exe --screenshot <png>
urbanchain.exe --screenshot-route <png>
urbanchain.exe --screenshot-line <png>
urbanchain.exe --screenshot-transfers <png>
urbanchain.exe --lang zh|en --screenshot <png>
```

已知限制：

- 背景是模拟城市的矢量要素（区域、边界、河流、海岸、山脉），不计划接入真实地理数据；
- 线路平滑由 Catmull-Rom 自动生成，尚未存储/编辑逐段精细轨迹点（fine trajectory）；
- 时间相关 Dijkstra 假设 FIFO；分时段间隔边界处可能出现非 FIFO，留到 v4 实验处理；
- 线路最短长度、换乘默认值等仍使用可配置默认值。
